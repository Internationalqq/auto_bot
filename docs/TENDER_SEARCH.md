# Поиск ЕИС и продолжение документов

Обычный `autobot.main` всегда выполняет свежий поиск. `--catalog-only` сохраняет карточки и не стирает незавершённое скачивание. Кнопка «Найти тендеры» открывает условия поиска: регионы, темы, границы суммы, давность, число страниц на сочетание региона/темы и общий предел закупок. Начальные три региона, две темы и цена 20–100 млн доступны как явно подписанный профиль; пользователь может изменить его или создать другой. Сохранение профиля и запуск — отдельные действия. Запуск получает текущие условия формы, даже если они не сохранены в профиль.

В `data/search_profiles.json` хранится до 20 общих для рабочего AutoBot профилей, файл до 128 КиБ. GET/POST `/api/tender-search-profiles` работают под существующей защитой маршрутов CRM и проверкой источника изменяющего запроса. Скрипт формы отдаётся через защищённый `/tenders/search-profiles.js`. Новый файл создаётся только при сохранении; до этого возвращается встроенный профиль. Запись атомарна под межпроцессной блокировкой; версия списка защищает от перезаписи чужой правки, повтор того же сохранения не создаёт новую версию. Повреждённый файл не заменяется настройками по умолчанию. Запуски и прежние рабочие данные не мигрируют; сам JSON и lock исключены из Git. Выбранный профиль запоминается в браузере, условия сохраняются на сервере.

`POST /api/tender-search/start` дополнительно принимает `search_profile` (ID) либо `search_filters` (полный снимок), без их смешивания. Снимок содержит `regions`, `keywords`, `price_min_kopecks`, `price_max_kopecks`, `needed_stage`, `days_back`, `max_pages`, `max_tenders`. Цена — целое число копеек от нуля до 1 трлн рублей; `null` означает отсутствие соответствующей границы, ноль остаётся явным нулём. Неверный диапазон, неизвестные поля, пустые темы и превышение лимита отклоняются. Неизвестная цена закупки остаётся причиной отсева, даже если границы суммы не заданы. Допускается 1–10 регионов, 1–20 тем и не более 60 их сочетаний. Общий бюджет времени поиска действует независимо от этих чисел. Этап пока фиксирован: «Подача заявок». Регион используется в текстовом запросе ЕИС; совпадение места исполнения этим не подтверждается.

Старые Flask API `/api/start-parse` и `/api/search-profiles` сохранены как алиасы для существующих потребителей. В production пользовательские вызовы используют новые маршруты с префиксом `tender`: именно эта группа проксируется в AutoBot текущим Nginx. Не расширяйте публичный доступ для исправления маршрутизации; общий префикс `/autobot/` также сохраняет свою защиту.

CLI поддерживает `--search-profile ID` и `--search-filters-json JSON`; профиль/снимок задаёт все условия, включая давность и пределы страниц/закупок. Веб передаёт дочернему процессу уже проверенный снимок, поэтому изменение профиля после нажатия не меняет выполняющийся поиск. Вызовы без новых параметров сохраняют прежние значения CLI; редактирование профиля не меняет глобальные константы процесса.

Продолжение документов выполняется только с `--resume-downloads`. Для новых запусков профиль/снимок сохраняется в checkpoint, а продолжение восстанавливает его независимо от последующих изменений профиля. Подпись и согласованность условий с параметрами проверяются. Для прежних checkpoint без снимка нужны те же `--max-pages`, `--max-tenders`, `--days-back` и неизменённые исходные регионы/слова/диапазон/этап; прежняя подпись сохранена. В веб-интерфейсе отдельная кнопка появляется при пригодном checkpoint; API берёт его прежние параметры и игнорирует новые условия запроса. `POST /api/start-parse` принимает `search_mode: "fresh" | "resume"`, по умолчанию fresh. Для resume каталог отключается. Старые вызовы без search_mode сохраняются как новый поиск.

Checkpoint пригоден 24 часа от начала поиска; дата должна содержать часовой пояс, фильтры совпадать, а необработанные ID оставаться. Прежние файлы без версии 2 не исполняются автоматически. Они сохраняются перед заменой. `SEARCH_RESUME=0` отключает запись и продолжение, интерфейс это учитывает.

`data/search_resume_checkpoint.json` остаётся указателем текущего скачивания. Перед заменой новым полным поиском или закрытием копия с контрольной суммой сохраняется в `data/search_runs/checkpoint-<sha256>.json`. Обновление указателя атомарно; ошибка до замены не повреждает прошлый файл. Никакого переноса старой рабочей БД при выпуске нет. Не полученные документы не попадают в completed_ids: повторяется только незавершённая часть. Нулевое число распознанных строк учитывается отдельно от успешного скачивания. Полный процесс парсинга и версионирование всех результатов ещё не превращены в устойчивую очередь.

Два одновременных общих поиска запрещены файловой блокировкой, включая запуск через CLI и веб. Точечные операции отдельного тендера сохраняют свой путь. Кнопка поиска каталога не запускает дополнительное обновление этапов всех старых карточек; полный запуск сохраняет настройку REFRESH_CACHED_STAGES.

Для поиска действует бюджет `EIS_SEARCH_TIMEOUT_SEC` (600 секунд по умолчанию, 60–3600). Перед следующим запросом проверяется остаток времени; timeout навигации ограничивается им. Две подряд неудачные страницы завершают текущую комбинацию региона/слова. Нераспознанная выдача не считается доказательством отсутствия закупок; CAPTCHA не обходится. Ошибка одной карточки сохраняет остальные. Уже начатые операции браузера имеют свои таймауты; это не жёсткое ограничение времени всего скачивания и парсинга.

В `last_search_run.json` и `search_runs/<run_id>.json` сохраняются условия, число карточек, уникальных закупок, прошедших фильтры до ограничения, выбранных, уже известных и новых. Причины отсева считаются отдельно; одна закупка может иметь несколько причин. Неизвестные цена/дата и будущая дата не проходят соответствующий фильтр. Граница давности включает весь бизнес-день. Дата вычисляется при проверке через `business_time.today_iso()` с `PMBI_TZ_OFFSET_HOURS=5` по умолчанию, как в CRM.

`GET /api/parse-status` дополнен search_summary и search_resume. Сохранённое состояние searching/downloading без живого владельца блокировки показывается как interrupted; файл истории при чтении не меняется. Полностью недоступная выдача завершает запуск ошибкой; частичная выдача сохраняется с предупреждением. Эти поля не измеряют полноту рынка или прибыль тендера.

При откате сохраняйте актуальные checkpoint, search_runs и search_profiles отдельно: не заменяйте рабочие файлы старым backup. Версия до профилей игнорирует их JSON и не умеет восстанавливать новый снимок условий; не продолжайте через неё поиск с изменёнными условиями. Для версий до явного возобновления требуется отключить SEARCH_RESUME и избегать нового каталожного запуска до возврата исправленной версии. Предпочтителен адресный выпуск исправления.
