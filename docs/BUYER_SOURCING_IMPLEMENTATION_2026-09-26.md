Уточнение пользователя: нужен максимально автоматический скрипт и результат
«название — цена — контакт — сообщение — статус», без фотографий и витрины компаний.

Реализовано: позиции → сохранённый поиск новых сайтов/исполнителей → проверка
страниц и контактов → автоматическое общее обращение по компании → JSON/текст.
В режиме email обращения автоматически проходят повторную проверку контакта
и попадают в действующую очередь отправки. Режим выбирается один раз при запуске.
Сохраняются прежний реестр, обращения, sent/uncertain, цены сметы, права и старые API.

## План миграции первого пакета

Только новые таблицы в buyer_outbox.sqlite3: buyer_search_runs,
buyer_search_steps, buyer_search_candidates и индекс очереди. Таблицы outbound,
outbound_attempt_history, buyer_replies и buyer_reply_prices не изменяются.
Инициализация новых таблиц транзакционная, идемпотентная, выполняется при первом
запуске поиска или включённого worker. Обычное чтение при отсутствии новой схемы
возвращает пустой список. Переноса/перезаписи рабочих записей не требуется.

Перед выпуском: SQLite online backup всех buyer-БД, integrity_check копий,
хеш упорядоченных значений старых таблиц; сохранённый образ для отката.
После выпуска: сверка старых значений, нового API без авторизации, версии assets,
health. Тестовые строки — только в отдельной БД. Откат к прежнему образу оставляет
новые таблицы на месте, запрещено заменять актуальную БД резервом.

## Управление без интерфейса

На сервере AutoBot:

```sh
python -m autobot.buyer_run start --tender-id TENDER_ID
python -m autobot.buyer_run start --tender-id TENDER_ID --send
python -m autobot.buyer_run report --tender-id TENDER_ID --format text
python -m autobot.buyer_run report --tender-id TENDER_ID --format json
```

Первый вариант готовит сообщения, второй разрешает email для найденных компаний.
Повтор того же запуска возвращает тот же run_id. `--position KEY` можно повторять.
`BUYER_DISCOVERY_WORKER=1` включает восстановление и фоновые шаги независимо от GET.
CLI `work --once` исполняет один шаг; длительный `work` используется для отдельного
процесса вместо встроенного worker. Не нужно держать страницу открытой.

HTTP сохраняет CRM-сессию и существующую проверку роли:
`POST /api/tenders/<tid>/buyer/jobs` с action=search_suppliers,
position_keys (необязательно), delivery=draft|email. По умолчанию draft.
`GET /api/tenders/<tid>/buyer/report?format=text|json&run_id=...` выдаёт результат.
`status=completed` описывает поиск и подготовку; статусы отправок/ответов — у компаний.

Поиск: запрос по профилю компании + запросы точных материалов; работы также через
индекс Авито. До 10 разных доменов/объявлений за запрос и до 300 проверок на запуск.
Достижение лимита и недоступность источника явно отмечаются как частичный результат.
Бесплатный резерв — Brave через DDGS и Bing RSS. Для штатного Yandex Search API
предусмотрены BUYER_SEARCH_API_KEY и BUYER_SEARCH_FOLDER_ID в окружении сервера.
Реальная интеграция Yandex не проверена: ключа в окружении нет.

Ни цена из сниппета, ни похожий материал не становятся ценой позиции. Опубликованная
цена сохраняется отдельно от ответа и экономики. Поля сметной цены/бюджета не выходят
за границу нормализации. Снимок включает объём, единицу, требования и регион.
При изменении сметы старый запрос блокируется перед постановкой и выдачей sender;
текстовый/JSON-отчёт помечает старую версию. Перезапуск не создаёт повторного письма.

Входящие и исходящие чередуются. Они не могут одновременно занимать рабочий браузер.
После перезапуска reader возобновляет тот же token и журнал/AI-run; другая машина
не забирает неизвестную попытку. Неопределённый запуск reader приостанавливает
отправку до сверки; создание второго AI-run не используется как восстановление.

## Ограничения и следующий шаг

Действующая отправка остаётся mailru_lite_script на Mac; входящие — один профиль
autobot-mail. SMTP/IMAP не переключены: пароль приложения не предоставлен.
Авито найденные страницы/контакты и текст сохраняет, исходящий адаптер не включён:
рабочий авторизованный аккаунт/API не предоставлен. Telegram/WhatsApp/MAX также
не отправляют без подключения; наличие ссылки не считается правом бота писать.
PDF/XLSX-вложения и общая цена за комплекс сохраняются прежним inbox как факт
ответа без автоматического построчного разбора. Полная переписка с живым ответом
новой компании в этом выпуске не проверена; тесты не посылают реальные письма.
