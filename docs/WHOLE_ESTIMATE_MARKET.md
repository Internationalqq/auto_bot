# Поиск цен по всей смете

19 сентября 2026. Бесплатный web-поиск, Авито/Hermes отложены.

## Запуск и результат

«Найти недостающие цены» открывает очередь. Без выбранных строк основная кнопка ставит все подготовленные позиции без подтверждённой цены. Выбранные строки проверяются отдельно. Ограничение старого вызова API (20/50) сохранено для прежних клиентов; новый `scope=all_without_verified` проходит всю смету, `scope=selected` обрабатывает весь переданный выбор (до 5 000 ключей). Обрабатываются строки текущей распознанной версии, а не неизвестные парсеру строки исходного документа.

Один SQL-план очереди хранит каждую позицию и сводку исходной готовности. Повтор не создаёт дубли активных заданий. Материалы/товары идут первыми; внутри группы приоритет выше у большей суммы. Другая вкладка или перезапуск не теряют очередь. Число обработанных заданий отличается от числа найденных цен.

«Остановить поиск» вызывает `action=cancel_pending` на прежнем POST-маршруте: отменяет ожидающие и текущие поиски только данного тендера и режима. Принятый пакет публикации завершает сохранение. Повтор остановки безопасен; чужая очередь и режим Авито не затрагиваются.

Фильтр результата показывает подтверждённые цены, кандидатов, уточнение исходников, ещё не обработанные строки, отсутствие цены после поиска и ограничение источника. Пустая цена не становится нулём или прибылью. Доставка, налоги, накладные и резерв по-прежнему вводятся для тендера пользователем.

## Подтверждение

`market_requirements` сохраняет исходное имя/единицу и явно указанные признаки: размеры, сечение, марку кабеля/бордюра, IP, плотность, фасовку, узнаваемый бренд/продукт. Эти признаки сохраняются в запросах; сравнение действует и на чтении старых результатов. Неизвестная единица, в том числе `1.0`, не подменяется штуками. Название материала не превращается в работу из-за слова «монтаж» в назначении или разделе.

Каталоги — начальный маршрут. Следующие запросы продолжают бесплатный HTTP-поиск; каждая позиция получает свой бюджет браузерных страниц. Блокировка источника сохраняется в отрицательном кеше. Реестр дополнен каталогами сухой штукатурки и силового кабеля Ярославля. Он не содержит цен.

Проверка страницы исключает блоки рекомендаций, не заимствует название товара из поискового запроса для безымянной микроразметки и не принимает `AggregateOffer/lowPrice` за точную цену. Цена, единица, модель, регион и дата всё равно проверяются существующим контрактом. Для сравнения нужны страницы реальных поставщиков, а не числовой ответ ИИ.

## Проверки и границы

Полный изолированный набор: **884 passed, 2 skipped, 20 subtests passed**. Шесть существующих Node-наборов прошли. Chrome 390/768/1280: 60 строк поставлены, отменены и прочитаны после обновления; проверены фильтр уточнений, длинные названия, ошибка сервера, сохранение выбора и отсутствие горизонтального переполнения. Более крупная очередь: 120 позиций завершены, 1 205 учтены без лимита истории. Исходные рабочие данные не менялись.

Паспорт пока охватывает узнаваемые признаки; состав заказных изделий и комплексных работ требует уточнения. Бесплатные поисковики могут ограничивать доступ. Отсутствие опубликованной цены остаётся явным пробелом. Gemini не подключён: без доступа к API модуль работает сам; платные API, ключи, расходы и отправка смет не добавлены. Широкая точность и охват по регионам ещё не доказаны.

## Проверка на рабочей смете, 19 сентября

Контрольный запуск четырёх разных материалов тендера 0171200001926000664 обнаружил конкуренцию старого внешнего исполнителя Mac mini с серверным поиском. При включённом `MARKET_WEB_WORKER` внешний `/api/agent-market/v1/claim` теперь выдаёт только задания Avito; явный запрос `mode=web` возвращает пустой результат. Сервер забирает web-задания внутри процесса. Когда серверный исполнитель выключен, прежний внешний web-контракт сохраняется. Уже выданные задания не переоформляются: одно активное внешнее задание контрольного запуска отменено обычным API.

Проценты, найденные предложения и журнал в модальном окне теперь относятся к последнему запуску. Старые попытки не превращают начало проверки четырёх строк в «97%». Сводка всей очереди сохраняется в API; остановка доступна и при продолжающихся заданиях другого запуска.

Наблюдаемый результат для повторной проверки: ровно четыре выбранные позиции, только серверный исполнитель; отдельный учёт найденных и принятых цен; исходная смета неизменна. Проверки выполняются на изолированной копии. Завершение поиска само по себе не доказывает пригодность цены для расчёта; итог живого прогона сохраняется отдельно.

Проверки исправления: 67 Python-тестов и 9 подтестов прошли (серверный исполнитель, внешний API, очередь, сохранение результата); новый Node-набор проверяет, что прошлые 121 задание и принятая цена не попадают в текущий запуск из 4 позиций, включая завершение и повторное открытие. Первое падение проверки токена оказалось утечкой переменной окружения в обновлённой тестовой фикстуре; порядок восстановления исправлен, все четыре набора повторно прошли. Полный набор из предыдущего выпуска повторно не запускался.
