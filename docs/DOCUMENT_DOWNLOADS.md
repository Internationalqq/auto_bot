# Загрузка текущего комплекта ЕИС

`main.download_file` сохраняет прежний результат `(Path, original_name)` или `None`. Скачивание выполняет отдельный `document_download.py`: HTTP-ответ читается потоком, файл публикуется после успешной проверки. [Requests](https://requests.readthedocs.io/en/latest/user/advanced/#body-content-workflow) требует явного закрытия потокового ответа; обработчик использует контекстный менеджер.

На документ: 128 МиБ, 90 секунд общего времени, 15 секунд соединения и 20 секунд ожидания данных. Родитель останавливает зависший процесс; у ребёнка есть собственный watchdog на случай остановки родителя. На Linux ограничены память до 256 МиБ, CPU и выходной файл; на Windows ограничение памяти ОС не устанавливается. Временные cookies/запрос хранятся в собственном временном каталоге и не попадают в журнал. Исходные настройки TLS сохраняются.

Отклоняются пустой ответ, HTML вместо файла, HTTP 206, несовпадение Content-Length без транспортного сжатия, превышение размера и нарушенная структура ZIP/Office. CRC всех элементов ZIP/RAR проверяет последующая ограниченная распаковка; скачивание не объявляет содержимое архива полностью проверенным. Расширение распознаваемого документа восстанавливается даже у URL вида `download.html`. Байты оригинала не переписываются.

`document_bundle.py` принимает до 100 ссылок и 512 МиБ за 600 секунд скачивания. Навигация по вариантам карточки использует отдельный общий срок 180 секунд; стандартные таймауты браузерных операций остаются дополнительным ограничением. Сбой хотя бы одного ответа останавливает новый разбор: скачанные временные файлы удаляются, прежние активные документы и отчёт сохраняются. Активация начинается только после получения всех ответов. Если сбой произошёл при самой активации, журнал остаётся неуспешным, разбор запрещён, заменённые редакции доступны через существующие версии/корзину. Это не транзакция сразу над всеми файлами.

`reports/DOCUMENTS_<tender_id>.json` хранит состояние loading/complete/failed и точный список текущих имён, размеров и SHA256. Запись атомарна, одновременно один загрузчик на тендер. Повтор одинаковых байтов не создаёт копий; разные документы с одинаковым именем получают суффиксы SHA. Старые файлы, отсутствующие в новой выдаче, остаются на диске, но не входят в новый разбор. Очистка дублей сохраняет имена из текущего журнала, при незавершённой загрузке откладывается. Незавершённые `.autobot-*` файлы скрыты из списка и прямого скачивания.

Повторный разбор использует текущий журнал и проверяет размеры/SHA перед чтением. Если журнала ещё нет, сохраняется прежний выбор из downloads; автоматической миграции каталогов нет. Контроль изменения источника во время самого OCR/Excel-разбора и ограничение этого парсера остаются отдельным этапом. Изменившийся состав документов входит в версию справочных данных для CRM; время одинаковой успешной повторной загрузки само по себе её не меняет.

В карточке есть «Повторить скачивание» при ошибке и «Обновить документы из ЕИС» в меню. POST `/api/tenders/<id>/refresh-documents` использует HTTPS-адрес ЕИС из каталога, резервирует процесс до старта потока, отвечает 202 с run_id. Повтор при занятом процессе — 409; запрет чужого Origin сохраняется. Публичный доступ к API закрывает существующая сессия CRM на Nginx. `/api/parse-status?tender_id=<id>` добавляет состояние документов; страница восстанавливает отображение выполняющегося задания после перезагрузки. Перезапуск веб-процесса не продолжает OCR автоматически: сохранённое loading остаётся незавершённым и допускает явный повтор.

Новая БД не создаётся, существующие таблицы и сценарии экономики не мигрируют. При откате журнал сохраняется, старая версия его игнорирует и снова использует прежний выбор файлов — это ограничение отката нужно учитывать перед повторным разбором. Выпуск не доказывает доступность ЕИС с сервера и точность всех распознанных строк.
