# Поиск рынка для загруженной сметы

Ручные сметы используют ту же SQLite-очередь, ограниченный серверный web-поиск
и сохранение результатов, что и тендеры. Поток внутри Flask и его память удалены.
Закрытие страницы не останавливает работу; перезапуск исполнителя возвращает
просроченное задание в очередь. Уже принятые ответы публикуются без нового поиска.

## Контракт

Существующие URL `/api/estimates/<id>/market-start`, `market-status` и
`market-stop` сохранены. Start принимает `city`, `selected_types` и необязательный
`operation_id` (UUID либо 32 шестнадцатеричных символа). Браузер сохраняет ключ
в sessionStorage до POST. Повтор одинаковой операции возвращает прежний `run_id`
и `duplicate: true`, в том числе после завершения. Изменение условий или исходных
строк с прежним ключом даёт 409. Новый клиентский запуск создаёт новый ключ.

План и все позиции принимаются одной транзакцией. Пустые имена не ищутся,
неизвестные типы отклоняются; предел — 50 000 исходных строк без усечения.
Одинаковые названия в разных физических строках не склеиваются. Старым строкам
без координат назначается стабильный идентификатор из сметы и исходного номера.
Внешний API исполнителя не выдаёт задания `estimate:*`; их берёт серверный
web-исполнитель. Сейчас поддерживается только `sources: ["web"]`.
Авито прямо обозначено в карточке как неподключённый источник.

Status без параметра возвращает последний запуск; `?run_id=...` — конкретный.
Счётчики считаются по всем заданиям запуска, без ограничения списка 1000 строк.
`applying` остаётся активным состоянием. Ошибки и отмены показаны отдельно,
`result_ok` не становится успешным при частичном сбое. Служебные leases и
сохранённый внутренний результат в ответ не попадают. Журнал содержит последние
восемь состояний позиций, а не непрерывную подробную трассировку поисковика.

Stop принимает необязательный `run_id`. Устаревшая вкладка не может остановить
новый поиск; повтор завершённой остановки безопасен. Без ключа сохранена
совместимость прежнего API: останавливается текущий запуск. Уже сохранённые
предложения остаются в отчёте. Удаление сметы с активным поиском отклоняется.

## Доказательства и восстановление

Задание фиксирует город, типы, SHA всех распознанных строк и физическую позицию.
Перед публикацией заново проверяются исходные данные, последняя операция и город.
Запоздалые ответы отменённого или заменённого поиска не применяются.
Используются общие проверки цены, единиц, региона, характеристик и срока давности.
Кандидат без доказательства цены остаётся источником для проверки и не входит
в экономику. Пустое предложение создаёт диагностическую строку, без `nan`-ссылки.

`market_sources.xlsx` — канонический сохранённый рынок. Под блокировкой сметы
сначала атомарно заменяется производный `market_compare.xlsx`, затем исходный
рынок. Карточка и экспорт заново строят сравнение по текущим строкам и каноническому
рынку; при новом запуске и отсутствии рынка частично записанное сравнение не
используется. Если процесс погиб после записи файлов, но до commit очереди,
сохранённый ответ повторно публикуется без дубля и нового запроса поставщику.
Повреждённый существующий файл рынка не подменяется пустым результатом.

Порядок блокировок при приёме/доставке: запись очереди → файл сметы.
Удаление: файл сметы → только чтение очереди. Исправление сметы должно соблюдать
тот же порядок и не запрашивать запись очереди под файловой блокировкой.

## Хранилище и выпуск

В существующей `agent_market_jobs.sqlite3` при первой записи создаются только
`uploaded_market_runs`, `uploaded_market_run_jobs` и индекс последнего запуска.
Новые таблицы связаны внешними ключами; план неизменяем и проверяется SHA.
Чтение не создаёт отсутствующую БД или таблицы. Прежние записи не переносятся,
старые таблицы и файлы смет не преобразуются. Новых зависимостей и секретов нет.

До выпуска: проверенная SQLite backup/restore, сохранённый образ, отсутствие
активных основных, ручных, рыночных заданий и парсеров. Образ проверяется отдельно
без сети. Откат на прежний исполнитель допустим только без активных заданий
`estimate:*`, включая принятые ответы `applying`: прежний код не знает их контекст.
Таблицы и файлы с историей сохраняются; удаление записей или восстановление старой
БД поверх новых пользовательских операций не является обычным откатом.

## Проверки

`tests/test_uploaded_market.py` проверяет границы API, транзакцию, параллельный
приём, физические строки, общий исполнитель, подтверждённые цены, отмену, смену
исходника/города, повтор доставки и неповреждение старого рынка.
`tests/test_uploaded_market_processes.py` останавливает настоящие процессы до и
после commit, во время lease и после записи файлов, а также запускает два приёма.
`node tests/estimate_workspace_frontend_tests.js` проверяет ключ браузера,
потерю ответа, повтор после обновления и точную остановку.

Визуальная приёмка проводится на отдельной БД при 390/768/1280 px. Синтетические
ответы проверяют интерфейс и восстановление; они не доказывают полноту рыночного
поиска. Приёмка реальных цен на размеченной выборке остаётся отдельной работой.
