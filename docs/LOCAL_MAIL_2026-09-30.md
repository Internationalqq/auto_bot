# Локальная почта AutoBot

## Текущий контракт

После ответа HOSTKEY пользователь выбрал минимальный риск для VPS и быстрый
скриптовый процесс. Поиск, сметы, очередь и история остаются на сервере;
SMTP и IMAP исполняет выбранный компьютер. Открытие SMTP/PTR на VPS не требуется.
Ни Hermes, ни браузер, ни ChatGPT для этой цепочки не запускаются.

`buyer_local` запускает `buyer_mail_service` отдельным процессом. Постоянный
идентификатор устройства, журнал отправки и блокировка ОС защищают повторный
запуск. `stop` создаёт запрос остановки: текущая операция завершается, следующая
не берётся. Неопределённая отправка никогда не повторяется автоматически.
Глобальная серверная очередь сохраняет свои lease и защиту повторных операций.

Почта требует включённый компьютер и сеть. После перезагрузки её запускают
явно; автозагрузка и планировщики не установлены. Закрытие Codex не завершает
процесс. Проверка существующих переписок назначается сервером каждые 10 минут;
в работе очередь опрашивается каждые 10 секунд. При отсутствии связи задания
остаются на сервере. Архив текстов не превращается в автоматическую рассылку.

## Установка и управление

Нужен Python 3.11+ и `pip install -r requirements-mail.txt`. Копия пакета
`autobot` должна быть доступна этому Python; полноценные зависимости web/AI
не нужны. Windows установлен в `%USERPROFILE%/PMbi/AutoBot` со своим Python
и минимальными пакетами, независимо от рантайма Codex. Установка в LocalAppData
из MSIX-приложения может перенаправляться в его LocalCache; физический путь
проверен через GetFinalPathNameByHandle. Worker запущен через системный WMI,
отдельно от дерева процессов Codex. Windows ACL каталога:
только текущий пользователь и SYSTEM. На macOS/Linux каталог 0700, секреты 0600.
Нельзя коммитить конфигурацию с секретами или копировать их в аргументы команд.

Пример конфигурации (заменить абсолютные пути и идентификатор устройства):

```json
{
  "worker_id": "local-device-unique-id",
  "local_control": true,
  "sender_mode": "smtp_imap",
  "inbox_mode": "smtp_imap",
  "draft_mode": "template",
  "collect_replies": true,
  "queue_url": "https://CRM-HOST/autobot/api/agent-market/v1/buyer",
  "queue_token_file": "/PRIVATE/queue_token",
  "mail_password_file": "/PRIVATE/mail_password",
  "outbox_dir": "/PRIVATE/journal",
  "sender_email": "WORKING-ACCOUNT@mail.ru",
  "smtp_host": "smtp.mail.ru",
  "smtp_port": 465,
  "smtp_security": "ssl",
  "imap_host": "imap.mail.ru",
  "imap_port": 993
}
```

Пароль приложения можно ввести через интерактивный
`python -m autobot.buyer_mail_service configure --config /PRIVATE/config.json`.
Ключ очереди предоставляется отдельно; это BUYER_WORKER_TOKEN, не market token.

```text
python -m autobot.buyer_local check --config /PRIVATE/config.json
python -m autobot.buyer_local start --config /PRIVATE/config.json
python -m autobot.buyer_local status --config /PRIVATE/config.json
python -m autobot.buyer_local stop --config /PRIVATE/config.json
```

При переносе на другое устройство сначала штатно остановить прежний worker,
сохранить журнал, настроить новый worker_id и проверить подключение.
Не удалять журнал ради повторной отправки. Неопределённые старые попытки
подлежат отдельной сверке, а не сбросу.

## Статус на сайте

`POST /api/agent-market/v1/buyer/service/status` использует существующий ключ
исполнителя. Принимаются только четыре boolean-поля; текст писем, ошибки,
пароли и клиентское время не публикуются. Сервер записывает своё время и
хранит максимум восемь последних устройств. Через пять минут без heartbeat
состояние offline. Штатная остановка публикуется сразу. Статус устройства,
которое остановлено, не скрывает другое активное устройство.

Работа локальной почты имеет приоритет над старым server-mail heartbeat.
Никакой миграции рабочих таблиц для этого не требуется.

## Проверки перед выпуском

Windows, изолированная копия: 176 tests + 36 subtests PASS — локальный процесс,
SMTP/IMAP, неопределённый DATA, повторный запуск, остановка, доступ и очистка
heartbeat, очередь, сообщения, pipeline и поиск. Реальный пароль приложения
проверен по SMTP и IMAP. Контрольное письмо направлено только в собственный
рабочий ящик: SMTP 250, копия сохранена в Sent; входящее письмо за время
проверки не найдено. Это подтверждение приёма SMTP, не доставки получателю.
Linux candidate и живое переключение отмечаются в CRM отчёте выпуска.
На macOS запуск в этом пакете не выполнялся; общая реализация проверяется
на Windows и Linux, но это не равно проверке macOS.

Локальный SMTP устраняет зависимость от портов VPS, но не отменяет правила
почтового сервиса или HOSTKEY о жалобах на размещённые ресурсы. В обращения
не добавляются ссылки на CRM; отправляются только согласованные запросы
реальным поставщикам. Полной гарантии от блокировок нет.
