# Общая база источников и повторный подбор Волги

Исходное состояние: AutoBot 2177f01, изменённый data/search_resume_checkpoint.json
и .impeccable сохраняются. CRM tracked diff пуст; пользовательские outputs сохранены.
Live: 213 закупочных строк, 29 сопоставимых цен (13,6%), 0 цен из ответов.
ЭТМ передал запрос в Ярославль; четыре входящих сообщения, цена не получена.

Наблюдаемый результат: проверенные публичные страницы одного тендера доступны
по идентичным товарам другого, с датой проверки и историей наблюдений. В новый
тендер передаётся только URL для повторной проверки, никогда чужие объёмы,
переписка или частные цены. Сайтовая цена не становится подтверждённой поставщиком.
Известные ссылки из Яндекса можно проверять отдельным идемпотентным draft-run;
никаких отправок при импорте. Общая очередь распределяет работу между тендерами.

Решение: используем существующие supplier_catalog_* и экран «База цен».
После сохранения проверки публичный HTML попадает в этот каталог: название
берётся с сайта, история и актуальность — из действующего механизма. Если
каталог не инициализирован, discovery продолжает работу без миграции.
Перед поиском читаем supplier_catalog_match, затем read-only проекцию истории
buyer_search_candidates: точное нормализованное имя/тип, работы по региону.
Цены и контакты — только из сохранённой проверки публичной страницы. Семь суток
означают свежесть проверки страницы, не срок действия коммерческого предложения.
Старые ссылки пригодны для повторного чтения. Ограничение выборки явно отражается.
Новые таблицы, миграция старых записей и изменения экономики не требуются.
Импорт записывает только новые публичные наблюдения штатными функциями каталога.
Перед production-прогоном отдельно резервируем вложенную market_index БД.

Проверки: изолированная БД, межтендерное переиспользование без утечки частных
данных, изменённые характеристики, устаревание и повторная проверка, повтор импорта,
недопустимые URL и равномерная очередь. Затем Linux candidate, резерв/откат,
production smoke и проверка ссылок пилота Волги через действующий inspector.

Следующий объём: самостоятельный локальный браузерный поисковик остаётся отдельной
работой; HTTP Яндекс 10/10 captcha, DDGS Yandex.disabled=True. Не запускать тот же
полный поиск снова как будто блокировка устранена. Используем уже найденные URL.
