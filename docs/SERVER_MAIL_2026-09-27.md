# Серверная почта без Mac и агентов

Сервис `python -m autobot.buyer_mail_service run --config …` использует обычные
SMTP/IMAP TLS и существующую HTTPS очередь. Настройки строго требуют
`sender_mode=inbox_mode=smtp_imap`, `draft_mode=template`, `collect_replies=true`.
В этом процессе нет перехода к агенту, модели или браузеру. Редактирование,
одобрение адресата и ручные сообщения проходят прежние проверки очереди.

Исходящие: один recipient, сохранённые subject/body, стабильный Message-ID,
долговечный журнал до DATA и после SMTP 250. `sent` подтверждает принятие
почтовым сервером, не доставку или прочтение. Копия в Sent через IMAP сохраняется
только после принятия SMTP. При неопределённом результате DATA сервис не
повторяет передачу. После аварии он сверяет Sent; отсутствие доказательства
остаётся `uncertain`. Полный текст тоже сверяется, включая цитируемый хвост.

Входящие: IMAP readonly/PEEK, поиск только метки обращения (для старой общей
темы — дополнительно точный отправитель). Собственные письма исключаются.
Изменённая вручную заявка не получает вымышленную привязку цен. Другой отправитель
с правильной меткой сохраняется, а сервер требует проверки его принадлежности.
Дедупликация по RFC Message-ID; известные web-ответы сравниваются по отправителю,
тексту и минуте. Несколько совпавших писем требуют сверки, не скрываются молча.
Режим каждые 10 минут задаёт прежний серверный планировщик, не Codex.

Ограничения: 2 МБ на MIME-письмо, 20 ответов за проверку, 200 результатов поиска,
100 папок. Превышение/ошибка даёт явный blocked, не ложное «ответов нет».
PDF/Excel вложения не анализируются; фиксируется факт ответа с вложением.
При нехватке подтверждения связь не заменяется агентом.

## Подключение и переключение

В CRM: `deploy/autobot-mail/setup.py` готовит config и копирует существующий
ключ очереди внутри сервера в `/opt/crm-secrets/autobot-mail` (0700/0600).
`password.sh` принимает пароль приложения через getpass в терминале самого
пользователя, без сети. `check.sh` проверяет TLS и вход, ничего не отправляя.
Журнал отдельный: `/opt/code/auto_bot/data/mail-transport`, монтируется постоянно.
В секретах нельзя хранить обычный пароль ящика. Нужен пароль внешнего приложения
с полным доступом к почте: https://help.mail.ru/mail/login/mailer/.

Контейнер определён в CRM `docker-compose.mail.yml`, profile `server-mail`.
Перед активацией: успешный check, резерв очереди, отсутствие sending/checking
и незавершённых Mac-заданий, остановка старых buyer sender/draft launchd-сервисов.
Затем `docker compose -f docker-compose.yml -f docker-compose.mail.yml
--profile server-mail up -d --no-deps autobot-mail` и проверка status/очереди.
Для отката сначала остановить новый сервис; нельзя запускать второй исполнитель
поверх незавершённой отправки. Сначала восстановить её прежним worker/journal.

При отсутствии SMTP или пароля приложение остаётся подготовленным, но не
запускается. Mac продолжает прежнюю работу до явного фактического переключения.
Telegram, Avito, WhatsApp и MAX этим транспортом не подключаются.

## Проверки

На изолированной копии 220 buyer-тестов и 33 subtests PASS.
Проверены разрыв DATA/перезапуск без дубля, SMTP отказы, точный текст, заголовки,
IMAP PEEK, тема/отправитель/дата, кириллица/HTML, вложения, цены и дедупликация.
Рабочих тестовых писем не отправляли. Актуальный результат выпуска и ограничения
ведутся в CRM `AUTOBOT_SERVER_MAIL_2026-09-27.md`.
