## Главный диагноз

Проект стал неудобным не из-за одной кнопки или цвета. Он вырос из MVP в рабочий комбайн:

- `autobot/web_ui.py`: 9263 строки, 42 Flask route, HTML/CSS/JS/API/CRM/jobs в одном файле.
- `autobot/main.py`: 2629 строк, поиск ЕИС, скачивание, распаковка, парсинг Excel/PDF, отчеты и CLI в одном модуле.
- `autobot/report_merge_html.py`: 2210 строк, расчет, форматирование и HTML-верстка отчета вместе.
- `data/` разрослась до нескольких гигабайт: много скачанных и распакованных файлов, но нет понятного экрана хранения/очистки.

Из-за этого пользователь видит не процесс, а набор технических операций: "пересобрать", "продолжить", "перезапустить", "недостающие", "рынок", "сводка", "CRM". Система требует помнить внутренний пайплайн.

## Цель новой версии

Сделать интерфейс не вокруг файлов и скриптов, а вокруг понятных рабочих объектов:

- Закупка.
- Смета.
- Поиск цен.
- Сравнение.
- Решение: брать / не брать / отправить в CRM.

На карточке должен быть один главный следующий шаг, а редкие технические действия должны уйти в меню.

## Этап 1. Центр статусов

Сначала нужен единый слой, который отвечает на вопросы:

- Какие закупки есть?
- Что по каждой уже готово: документы, смета, рынок, сравнение, HTML?
- Что надо сделать дальше?
- Что сейчас выполняется?
- Сколько места занимают данные?

Результат этапа:

- Новый модуль `autobot.workflow_overview`.
- API `/api/workflow-overview`.
- Дальше на этом API строится упрощенная вкладка `Тендеры`, без отдельного dashboard.

## Этап 2. Упрощенная вкладка `Тендеры`

Основной экран закупок:

- Верхняя строка: "Поиск", "Сметы", "Цены", "Сравнения", "Хранилище".
- Карточки закупок с одним главным действием.
- Фильтры: "нужна смета", "нужны цены", "готово к решению", "ошибки".
- Лог выполнения отдельно, не как центр интерфейса.

## Этап 3. Разрезать `web_ui.py`

План разреза:

- `autobot/web/app.py`: создание Flask app.
- `autobot/web/routes_tenders.py`: закупки и запуск пайплайна.
- `autobot/web/routes_estimates.py`: загрузка смет.
- `autobot/web/routes_market.py`: поиск цен и сравнения.
- `autobot/web/routes_crm.py`: экспорт в CRM.
- `autobot/web/jobs.py`: фоновые задачи и статусы.
- `autobot/web/templates/`: HTML-шаблоны файлами, без гигантских строк в Python.
- `autobot/web/static/`: CSS/JS отдельно.

## Этап 4. Разрезать `main.py`

План разреза:

- `autobot/eis_search.py`: поиск закупок.
- `autobot/eis_downloads.py`: документы и cookies.
- `autobot/archive_extract.py`: zip/rar/7z.
- `autobot/estimate_parser.py`: Excel/PDF в нормализованные строки.
- `autobot/estimate_reports.py`: XLSX/HTML отчеты по смете.
- `autobot/main.py`: только CLI-оркестратор.

## Этап 5. Хранилище и обслуживание
