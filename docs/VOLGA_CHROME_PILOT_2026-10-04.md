# Пилот поиска Иваном через Chrome

Поручение пользователя 4 октября: использовать существующего Ивана (Hermes,
профиль commercial) на Mac mini, только Google Chrome. Firefox и Safari не
трогать. Это разовый ограниченный пилот, не постоянная автоматизация.

## Исходное состояние

AutoBot 0f8ff95; чужие data/search_resume_checkpoint.json и .impeccable/ сохранены.
Волга 0171200001926000664: 40/213 сопоставимых цен. Выбраны 10 незакрытых
товарных строк из текущей сметы, исходный snapshot с position_key сохранён.
Действующая модель Ивана gpt-6-astra, reasoning medium не изменялась.

## Граница и проверки

Пять свежих сессий по две позиции; максимум 24 итерации и 210 секунд на пакет,
общая граница 900 секунд. Максимум две Google-попытки и три карточки на строку.
Только computer_use и file; без почты, отправок, заказов, делегирования и расписания.
Общий browser_lock берёт управляющий скрипт, освобождает только свой ticket
после завершения собственного процесса. Чужие браузеры/процессы не останавливаются.
Явный отказ инструмента или CAPTCHA останавливают пакет и весь пилот.

Профиль commercial имел устаревшее allowed_apps=[Safari]. По новому поручению
список заменён на [Google Chrome], актуальное правило внесено в SOUL.md и как
исключение в общий README. Остальные профили не менялись. Резерв на Mac:
/Users/egor/.hermes/profiles/commercial/workspace/chrome-pilot-backup-20261004-132427.

Первый запуск за 34 секунды обнаружил отсутствие computer_use в наборе: SSH
PATH не включал ~/.local/bin с уже установленным cua-driver. Действий в
браузере не было. Результат сохранён в preflight-batch-1, окружение запуска
исправлено; установка/обновление драйвера не выполнялись. Доступен v0.28.2.

## Артефакты и приёмка

Mac: /Users/egor/.hermes/profiles/commercial/workspace/volga-chrome-pilot-20261004.
input.json, run-state.json, batch-N/positions.json, prompt.txt, result.json и agent.log.
Цены модели сами по себе не являются подтверждением. Найденные URL проходят
обычный AutoBot enqueue_sources с проверкой актуальности строк и страниц.
Результат оценивается по реальному приросту comparable, источникам, ошибочным

должна остаться неизвестной, её нельзя объявлять нулевой.

Постоянный исполнитель и автоматическая передача задач из сайта пока не
внедряются: сначала проверяется работоспособность реального Chrome-пилота.

## Проверенный блокер запуска

Повтор после исправления PATH: session 20261004_132741_6fbff1, 108 секунд.
computer_use успешно получил окно «Новая вкладка — Google Chrome». Первый
type поискового запроса вернул `denied by user`. Причина установлена чтением
штатного CLI callback: он ждёт одобрения 60 секунд; в фоновом quiet-запуске
ответа нет, timeout возвращает deny. Это не CAPTCHA и не отказ Google.

Иван остановился, записал обе строки blocked, 0 запросов и 0 предложений.
Оставшиеся четыре пакета не запускались. Собственный browser_lock released.
Firefox/Safari не использовались. Отказ не обходился через AppleScript, CDP,
другой браузер или снятие подтверждений. Пользователю показан конкретный
объём и запрошено подтверждение действий Chrome после отказа инструмента.
До ответа дальнейшие действия браузера не разрешаются исполнителю.

AutoBot production и цены не менялись: исходное покрытие 40/213. Копии
result.json и run-state.json сохранены в локальных outputs/volga-20261004.

## Продолжение после подтверждения пользователя

На конкретный запрос разрешить ввод и клики только в Chrome для ограниченного
пилота пользователь ответил «ну делай что сделать надо?». Для этих запусков
добавлен локальный callback, который выдаёт `approve_once` только для разрешённых
действий Chrome, до истечения 900 секунд. Глобальное автоодобрение не включено,
ядро Hermes и его проверки запрещённых действий не менялись. Сохраняется аудит
действий; другие приложения, опасные сочетания и почтовые URL отклоняются.
Девять проверок ограничений callback прошли. В первой версии обёртки ошибочно
возвращался CLI-вердикт `once` вместо контракта `approve_once`; исправлено после
сверки с установленным CLI. Ошибочный запуск сохранён в callback-format-batch-1.

После исправления разрешений обнаружена отдельная проблема фонового ввода:
драйвер сообщал успешный type/return, но Google не открывался. Повтор с явным
cmd+l, затем с click адресной строки дал тот же результат: URL виден как текст,
вкладка остаётся новой. Артефакты navigation-batch-1 и background-keyboard-batch-1
содержат ноль предложений, собственные блокировки освобождены.

Установленный backend поддерживает `computer_use.keyboard_delivery_mode`:
для commercial включён `foreground`, с сохранением точного window_id, проверкой
окна драйвером и восстановлением фокуса. Резерв config-before-chrome-keyboard.yaml
лежит в каталоге пилота на Mac. Это проверка доставки клавиш в разрешённый Chrome,
а не обход отклонённого действия. Другие профили и шлюзы не перезапускались.

Foreground-ввод действительно открыл Google. Следующий capture выбирал Chrome
AXHelpTag: безымянную полоску URL 1640×22 вместо основной страницы 1920×975.
Это подтверждено отдельным read-only осмотром окон под browser_lock. Только в
процессе пилота добавлена узкая обработка: пустое дерево, безымянный Chrome,
высота screenshot <=32, ширина >=400; следующая свежая структура обязана
содержать и AXHelpTag, и AXWindow Google Chrome. Неизвестные окна не пропускаются.
Пять проверок распознавания прошли. Общий backend других профилей не изменён.

Первые пакеты открыли Google для ИБП, БОН, TRASSIR, SFP и коннектора. ИБП в
выдаче заменяется другим артикулом; это не принимается как совпадение. cmoshop
и DSSL закрывали соединение в Chrome. Для DSSL обычный curl с Mac тоже завершился
SSL timeout. Системный HTTP-прокси не включён; Karing disconnected, Tailscale
connected. Сеть и VPN не переключались.

Переданы два реально наблюдаемых URL в штатный draft-only enqueue_sources:
run f8c0e40c85e344f080b1942a1e64d7f3. Результат partial, отправок/campaign_ids нет.
cmoshop прочитан сервером: БОН-19-1-24-В, microdata 4950 руб., но единица цены
не установлена; price_checks unit-mismatch, в сопоставимые не включён. Подготовлены
пять черновиков по существующему каталогу для двух позиций, это не новые отправки.
Покрытие после этой проверки остаётся 40/213 (18,8%), confirmed=0.

При устаревшем адресовании элемента драйвер предписывает fresh snapshot. Это
отделено от отказа разрешений: допускается один свежий capture и новая адресация,
без отключения проверки принадлежности окну. Ограничение доступа конкретного
продавца также сохраняется отдельно: сайт не повторяется и не обходится,
оставшиеся независимые позиции продолжаются. Продолжение сохраняет исходный
900-секундный срок и историю прерываний, уже выполненные поиски не повторяются.
Для не начатой Digma предусмотрен шестой короткий пакет, если хватит исходного
времени. Полного успешного прогона на этом этапе ещё нет.

## Итог текущего пилота

Статус **incomplete**. Четыре коротких сессии; состоялись Google-запросы по пяти
из десяти выбранных позиций. По EKF ввод предпринят, но поиск не подтверждён;
Digma, ОГЦ, щит и ATEN не выполнены. В четвёртом пакете foreground type снова
сообщал Sent (unverified), а два capture оставались на старом Google-запросе.
Продолжение остановлено: нельзя считать ввод успешным по ответу драйвера.

Прямо в браузере получено 0 проверенных предложений. В штатной последующей
проверке двух найденных ссылок — один кандидат 4950 руб., 0 новых сопоставимых
строк. Волга остаётся 40/213 (18,8%). Прогона всех десяти и готового постоянного
поискового исполнителя нет; успешной production-автоматизацией пилот не является.

Все собственные browser_lock освобождены, временный consent закрыт немедленно.
Неудачный эксперимент keyboard_delivery_mode=foreground отменён: восстановлено
исходное значение только этого поля, allowed_apps=[Google Chrome] сохранено.
Firefox/Safari, шлюзы остальных агентов и глобальный драйвер не менялись.
Результаты сохранены на Mac в final-summary.json и локально в CRM
outputs/volga-20261004/chrome-final-summary.json. Отдельный поисковый API не
подключался; Hermes отметил сессии subscription_included, actual_cost неизвестен.

Следующая техническая задача — обеспечить проверяемую адресацию окна и доставку
ввода в Chrome, затем повторить один поиск как проверку запуска перед выдачей
пакета. Для эффективности ссылки из браузера следует читать существующим
скриптом: текущий пилот уже доказал, что cmoshop читается им при сбое Chrome.
Обычный пользовательский вход в почту или Google эту проблему не устраняет.

Проверки: 9 сценариев ограниченного callback, 5 сценариев распознавания полоски
Chrome, реальный ввод и capture, очередь draft-only и проверка итогового покрытия.
Общий тестовый набор AutoBot не запускался: код приложения не изменён. Изменения
пилота находятся в операционных скриптах; production-контейнер не перевыпускался.
