# Автономная работа почтового Hermes

Исходный код AutoBot: `153f253`, CRM: `b9c42d6`; посторонние изменения сохранены.
Первое письмо реально отправил Hermes, но Codex помогал управлять мешающим окном
и пробовал ввод текста через RustDesk. Это не доказательство полной автономности.

Наблюдаемые сбои: несколько профилей одновременно управляют одним Firefox;
глобальный backend CUA переживает задание и повторно использует завершённую сессию.

Пакет: расширение `desktop-queue` через штатные override и on_session_end Hermes.
Все участвующие профили используют один файловый lock на весь ход агента,
включая чтение экрана; исходный обработчик сохраняет ограничения инструмента.
Новая задача получает новую CUA-сессию. Ни ввод, ни отправка не переигрываются.
Статусы uncertain, дедупликация, журналы попыток и точный текст обращения сохранены.
Другие задания не удаляются; подключение профилей выполняется с резервной копией
конфигурации и штатным перезапуском после завершения текущих действий.

Проверка: реальная конкуренция процессов, освобождение после аварии, отдельные
сессии последовательных заданий, отсутствие повторного ввода и сохранение guard.
Затем два ранее заблокированных письма через очередь CRM и проверка ответов.
Подтверждением автономности считается выполнение без ввода/кликов Codex.

Ограничение: блокировка действует только для подключённых Hermes-профилей;
ручное управление Mac и сторонние программы она не блокирует. Если завершение
хода аварийно обходит hook, очередь безопасно удерживается до выхода процесса;
lock живого процесса не снимается по таймеру.

## Проверено и установлено

- 13 проверок на Mac PASS (изолированная временная папка, без браузера/почты).
- Реальная загрузка Hermes, tool override, два последовательных задания,
  on_session_end и сброс backend PASS на временном профиле с noop backend.
- Отдельно воспроизведён порядок запуска gateway: plugins загружаются раньше
  встроенных tools. Первоначальный override перезаписывался поздним импортом
  shim. Теперь shim импортируется перед override; проверка повторена PASS.
- Расширение установлено в `autobot-mail`, `gulya`, `zakup_alibert`.
  Каждый профиль штатно перезапущен SIGUSR1 после active_agents=0; сервисы running.
  Регистрация подтверждена audit-записями новых gateway PID 63267/63274/63273.
  Резерв исходного config каждого профиля:
  `backups/desktop-queue-20260926T091216Z/config.yaml`.
- Чужие правки ядра Hermes не изменялись. Интерфейс и БД CRM не менялись.
  Полный suite CRM/Hermes и адаптивный UI в этом пакете не запускались.

## Живой прогон: автономная отправка пока не подтверждена

Из CRM явно повторены два ранее blocked письма:
`ef9e6ae7c7c747fca2822ce1d516dd05` и `98ab81cea2134c76b03035f87702d3f9`.
Попытки `e5b00f981990b2b0c9101788` / `dcaac89d9704dc26c8c928ab` завершились
`Connection error` от модели. В первом запуске зарегистрирован только capture,
во втором инструментов не было. Проверяемый receipt не получен, поэтому CRM
консервативно сохранила uncertain; повторная отправка заблокирована.
Журналы и прежнее единственное sent-письмо сохранены. Ввод/клики Codex на Mac
в этом пакете не выполнялись.

Отдельный короткий API-запуск `run_e56a2139617d4d6fa0b62e43e58f789b` ответил OK.
Проверка отправленных `run_4575ec2d181e461698ce0c297b8f5824` и read-only probe
`run_e38110c45caa44f48b3b3e24cf80132b` также закончились ошибкой соединения.
Диагностика HTTP-клиента показала `RemoteProtocolError: Server disconnected
without sending a response`; отдельная попытка без инструментов восстановилась
после пересоздания клиента. Это нестабильность соединения, не доказанный диагноз VPN.
TLS/доступы/сетевые настройки не ослаблялись. Новых успешных отправок нет.

Следующий шаг: стабилизировать соединение Hermes с настроенной моделью;
затем только чтением сверить отправленные для двух uncertain, сохранить
доказательство и выполнить явное восстановление их статуса с историей.
Не сбрасывать uncertain и не запускать новую рассылку вслепую.

Откат: дождаться отсутствия активных заданий; восстановить config из указанного
резерва, затем штатно перезапустить только эти три профиля. Browser/CUA guards,
почтовые аккаунты, исходная очередь и core-файлы не менялись.
