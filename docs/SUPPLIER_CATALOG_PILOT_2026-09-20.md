# Каталог поставщиков: первый рабочий пакет

20 сентября 2026. Исходный AutoBot: `c706f2089240d37deeec658879078909a4ae74d8`.

## Поведение

В навигации смет и тендеров появился раздел **Поставщики и цены** (`/tenders/suppliers`). Строка содержит название товара/услуги со ссылкой, цену в исходной единице продажи, поставщика, регион, дату чтения и условия. Есть поиск, фильтры, история и отдельная вкладка источников. Отсутствующая цена не заменяется нулём, «от» сохраняется. Опубликованная цена ещё не означает соответствие конкретной смете.

SQLite рядом с существующим индексом хранит источники, предложения, сжатые страницы, неизменяемые наблюдения, задания и очередь ссылок. Суммы — целые копейки. Чтение пустой базы не создаёт её; повтор загрузки не дублирует записи. Изменение цены/условий и истечение срока требуют повторного сопоставления сохранённого предложения. Успешно исчезнувшие варианты исключаются из актуального каталога, история остаётся.

Поиск тендера сначала читает этот каталог, затем существующий индекс и прежний поиск. Для цены проверяются тип изделия, характеристики, единица, объём, регион и источник. Бетон для заливки не подменяет бордюр, работа по кирпичу не подменяет работу по бетону. Цена рулона не превращается в цену м², а ставка за 8 часов — в почасовую.

## Границы пилота

Подключены шесть выбранных разделов: прайсы Гамма-Бетон и ШтеттерБетон, геотекстиль Geo76, кабель АВБШв E-kc, электромонтаж СтройГарант, работы/техника Орион. Остальные семь записей реестра видны как ещё не подключённые. Это не полные каталоги всех сайтов и не проверка юридических лиц.

Обход использует открытые страницы и реальные ссылки пагинации/карточек, ограничения размера и числа страниц, robots.txt, паузу и проверку публичного адреса при каждом переходе. Задания сохраняются при закрытии страницы и перезапуске процесса; лимит продолжает тот же обход. Ошибка страницы сохраняет ранее полученные данные. Платного поиска, Авито, Hermes, переписки с поставщиками и новых модельных зависимостей нет.

Пилот прочитал 132 страницы выбранных разделов без сетевых ошибок. Сохранённые страницы повторно разобраны после исправлений извлечения. Каталог содержит 295 актуальных предложений, включая позиции без опубликованной цены. Точные финальные количества и сведения о выпуске записываются в CRM `AUTOBOT_SUPPLIER_CATALOG_PILOT_2026-09-20.md`.

Локальное сопоставление всех 127 строк «Волги» на копии заняло 4,141 с, нашло подходящие предложения для 6 строк (5 бетонных, 1 кабель). Это не рост покрытия относительно исходных 6 строк и не новый полный интернет-поиск/расчёт прибыли. Исходный отчёт не перезаписан. Работа импорта → БД → обычный поиск → публикация → проверка после изменения цены покрыта отдельным интеграционным тестом.

Следующие части: контрольная разметка требований, подключение источников под оставшиеся категории, импорт XLSX/PDF, однозначный пересчёт упаковок с кратностью покупки, повторная проверка наличия/доставки, плановое обновление и повтор только ошибочных страниц. Сейчас обновление запускается кнопкой. Работы с ценами «от» требуют точного предложения.

## Проверки

Изолированная копия проекта, отдельные SQLite, без ключей и сети для тестов. Финальный полный набор: **971 passed, 2 skipped, 27 subtests** (178,53 с). Три существующих frontend-набора и синтаксис нового JavaScript прошли. Проверены 390, 768, 1280 px; финальное независимое визуальное ревью — отдельная запись в `.impeccable/review/`.

Первая production-проверка обнаружила пропущенный запуск каталога в Gunicorn: основной Python entry point работал, но контейнер использует `post_worker_init`. Загрузчик подключён к этому существующему hook. Регрессионный тест запускает hook, обрабатывает сохранённое задание на отдельной БД без сети и проверяет отсутствие второго потока при повторном вызове. Затронутые worker/runtime/API-наборы после исправления: **14 passed**, 4,67 с. Полный набор выше выполнен до этого исправления; перед повторным выпуском дополнительно проверяется реальный старт Gunicorn-образа на изолированной БД.

## Миграция и откат

Применимый план выпуска для этого пакета:

1. Сверить HEAD, образы, защищённые маршруты и отсутствие активных парсеров/поиска. Не трогать чужие изменения и `data/search_resume_checkpoint.json`.
2. Создать закрытую резервную копию данных через SQLite backup API, проверить integrity/FK, восстановление и количества строк; сохранить файлы данных и старый образ. Исходный отчёт «Волги» проверить по SHA-256.
3. Собрать точный коммит. На отдельной копии производственного индекса дважды выполнить `supplier_catalog_store.initialize` и `seed_sources`; проверить 13 источников, integrity и неизменность всех прежних таблиц. Запустить старый образ с копией дополненной БД, проверить совместимость чтения.
4. Миграция v1 добавляет семь таблиц `supplier_catalog_*` и индексы в `data/market_index/market_prices.sqlite3`. Старые таблицы и сметы не преобразуются. Неизвестная будущая версия отклоняется до изменения схемы. Запуск рабочего процесса выполняет эту же идемпотентную инициализацию.
5. Переключить только AutoBot, проверить health, точную версию, UI/API, запрет анонимного доступа и cross-site POST. Сопоставить старые таблицы/отчёт с резервной копией. Потом явно запустить шесть источников и проверить итог импорта.
6. При неуспешной проверке остановить новые задания, вернуть сохранённый образ. Добавочные таблицы совместимы со старым кодом; их можно оставить. Восстановление всей БД требуется только при подтверждённом повреждении, с остановкой всех её писателей и учётом операций после резервирования. Не заменять рабочую БД демонстрационной и не удалять новые таблицы наугад.

Пути резервирования, версии, результаты репетиции и production-проверок сохраняются в отчёте после выполнения. Миграция не объявляется выполненной по наличию этого плана.
