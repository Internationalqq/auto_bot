Наблюдаемый результат: пять адресатов перепроверены по источникам, каждому
создано не более одного письма с уникальной меткой темы; отправка подтверждена
в «Отправленных». Исходящие/ответы связаны с компанией и строкой сметы, повтор
проверки не создаёт второй ответ. Цены/НДС/наличие/доставка сохраняются отдельно
от сметной цены; неизвестное не превращается в подтверждённое предложение.

Пакет: штатная отправка через Mac/рабочий Mail.ru; в теме стабильная метка
`[AB-…]`, тело подготовленного запроса сохраняется. Интервал inbox 600 секунд
вместо 1800; проверка lease/взаимного исключения с отправкой сохраняется.
Мониторинг должен отличать «ответа нет» от ошибки чтения почты. Результат
проверяется на изолированных тестах, затем в production. Копии БД/образов
для отката обязательны; рабочая смета и старые исходящие не переписываются.

Промежуточная проверка: ЭТМ и «Кабельные системы» отправлены, адресат/метка/полный
текст проверены в Sent. Вторая отправка получила задержанное подтверждение;
сверка `reconcile_sent` сохранила исходный uncertain в журнале, нового Send нет.

контакт с официальной страницы, прежняя неудачная проверка остаётся в истории.

Сборщик Hermes не вернул ответы из-за Connection error. Добавлен отдельный
режим `inbox_mode=mailru_lite_script`, использующий существующий Firefox/Mail.ru
и защиту окна/аккаунта. Скрипт ищет точную метку, проверяет полноту результатов и
распределение по папкам, пропускает Sent/Drafts до открытия, читает входящие.
Неполный поиск и ошибки фиксируются как blocked, а не «ответов нет». Полная
тема, отправитель, фактическая дата (точность UI до минуты), текст и снимок с
хешем сохраняются; вложения не открываются. Цена извлекается только для одной
строки и однозначной дословной цены за единицу, с обязательной проверкой
соответствия; ответ менеджера с другого адреса тоже требует проверки цены.
Данные писем не исполняются как инструкции. Смета не меняется.

Отправитель после одного Send ждёт подтверждение дольше, не нажимает повторно.
Отчёт связывает отправку с неизменяемым draft ID, показывает фактический email,
даже если официальный контакт обновился после поиска.

Проверки: 168 тестов buyer/hermes в изолированной копии Windows прошли. После
уточнения AXRow/рекламных блоков дополнительно прошли 12 тестов reader. Живой

Уточнение пользователя: всё должно исполняться самостоятельным скриптом,
без cron/heartbeat Codex и без зависимости от GPT. Созданный heartbeat
`automation-2` удалён через API приложения. Рабочая схема — существующий
launchd KeepAlive для `buyer_sender`: опрос очереди каждые 10 секунд, срок
проверки каждой переписки хранится в SQLite (`next_at`, шаг 600 секунд).
`buyer_mailru_inbox` читает почту и разбирает явные цены обычным Python;
он не запускает Hermes model API. Закрытие Codex не останавливает этот цикл.
