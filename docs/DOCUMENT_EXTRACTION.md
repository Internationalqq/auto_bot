# Распаковка документов тендера

Разбор берёт исходные архивы только из `data/downloads/<tender_id>`. Старое дерево `extracted` не становится дополнительным входом: вложенные архивы обходятся от исходника с единым бюджетом. ZIP и RAR читаются потоком через `zipfile.open` / `rarfile.open`; `extractall` и распаковка 7z прямо в рабочую папку не используются. Предварительная проверка имён нужна дополнительно к API библиотеки: [документация Python](https://docs.python.org/3/library/zipfile.html), [rarfile](https://rarfile.readthedocs.io/api.html).

На один тендер действуют ограничения: 64 архива, 2000 записей, 5 уровней вложенности, 128 МиБ на исходный архив и отдельный файл, 512 МиБ суммарно после распаковки, коэффициент сжатия не выше 500. Вложенный архив и извлечённые из него файлы входят в один счётчик. Повторное использование сохранённого результата также учитывается в общем бюджете. Процесс ограничен 120 секундами; родитель прекращает зависший процесс и его дочерние обработчики. На Linux дополнительно ограничены память, CPU и размер отдельного файла. На Windows используются установленные 7-Zip/UnRAR, включая стандартные каталоги вне PATH.

Отклоняются абсолютные пути, `..`, ссылки, специальные файлы, неоднозначные/повторяющиеся имена и коллизии файлов с папками. Заявленный и фактический размер проверяются; CRC проверяет архивная библиотека. Ошибка внутри вложенного архива не публикует частичный результат его исходного архива. Распаковка идёт в собственную временную папку; проверенное дерево публикуется переименованием. Исходные файлы не меняются.

Результат хранится внутри `extracted/<tender_id>/<original_stem>/verified-<version>`. Это сохраняет совместимость с существующим переносом старых исходников и их кеша в корзину версий. Для каждого файла журнал содержит относительный путь, цепочку исходных/вложенных архивов, размер и SHA256. Повтор проверяет исходник, политику, ограничения, размеры и хеши файлов. Изменённый производный кеш сохраняется под `invalid-*` и восстанавливается из исходника; он не становится входом для разбора. Версии и карантин автоматически не удаляются.

`reports/ARCHIVES_<tender_id>.json` фиксирует результат последнего запуска. При любой ошибке архива новый отчёт сметы не заменяет предыдущий. Общий поиск продолжает другие тендеры и сохраняет неуспешный для явного продолжения. В карточке видны причина и незавершённость, а прежний отчёт, если он есть, остаётся доступен. Одинаковые имена PDF в разных каталогах больше не объединяют количество распознанных файлов или официальные итоги: `ESTIMATE_PARSE_*` хранит отдельные записи источников. Прежние поля этого JSON сохранены; неоднозначный старый итог по одному имени не применяется сразу к двум файлам.

Поддержан обычный многотомный ZIP `.z01 … .zip`: до 100 томов, общий размер до 128 МиБ, ZIP32 с каталогом целиком в последнем томе. Во временной копии пересчитываются номера дисков и смещения по [публичной спецификации ZIP](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT); проверку заголовков, перекрытий и CRC выполняет стандартная библиотека. Внутренние поля Python не переписываются, исходные тома остаются неизменными. В журнал и ключ кеша входят имена, размеры и SHA всех томов. Версия политики — 2, прежний кеш сохраняется, новый разбор создаёт проверенную версию.

Основной разбор передаёт точный текущий список файлов, предпросмотр сверяется с журналом текущего комплекта. Совпадающие имена основы однозначно связывают тома. Исторические `doc_N.z01` / `doc_M.zip` допускаются только при единственном полном наборе и единственном ZIP в выбранном комплекте. Пропуск тома, дубли, лишний том, исключённая прежняя версия или отсутствие завершающего ZIP останавливают новый отчёт. Варианты ZIP64, каталог в нескольких томах, неоднозначные наборы и многотомный RAR требуют ручного открытия. Для составного предпросмотра общий вход ограничен 32 МиБ, чтобы временная сборка укладывалась в тот же предел записи процесса; превышение объясняется до создания временного файла.

Пока не поддержаны 7z и зашифрованные архивы; причина выводится явно. Этот механизм не доказывает полноту распознавания Excel/PDF, корректность коэффициентов, НДС или экономики; эти проверки — отдельные части A4/A6. Данные рабочей базы не мигрируются.

## Предпросмотр документов

Excel, DOCX, раскрытие ZIP/RAR и чтение выбранного файла внутри архива вынесены в отдельный процесс `document_preview_worker.py`. Общая блокировка `data/document-preview.lock` допускает один такой обработчик на приложение, включая несколько веб-процессов. Другой запрос не накапливается в очереди: пользователь видит предложение повторить просмотр. Изолированный обработчик не запускает поиск, не изменяет отчёты и не читает условия экономики.

Время ограничено 25 секундами; родитель прекращает процесс и его дочерние декодеры. На Linux дополнительно действуют 768 МиБ адресного пространства, 25 секунд CPU и 32 МиБ на выходной файл. Число потоков числовых библиотек ограничено одним. На Windows проверены остановка по времени и уборка; лимит памяти средствами ОС в этой реализации не устанавливается. Это изоляция ресурсов обработчика, не полноценная песочница исполнения.

Исходный файл ограничен 128 МиБ, выбранный элемент архива — 32 МиБ. Для раскрытия действует общий бюджет 16 архивов, 500 записей и 64 МиБ, три уровня вложенности. Повторное открытие вложенного архива не сбрасывает глубину. Используются те же правила безопасных имён, ссылок, повторов путей, сжатия и потокового чтения, что для основного разбора. Превышение общего бюджета не скрывает уже доступные документы без признака: список помечается частичным либо показывается причина недоступности.

Excel показывает до пяти листов, 100 строк и 30 колонок каждого; ограничены также длина ячеек и суммарный текст. Усечение отмечается явно. DOCX читает не более 8 МиБ основного XML. Обычный текст читается только до 2 МиБ; граница посреди UTF-8 не портит весь русский текст. Оригиналы скачиваются без изменения, PDF/изображения по прямому URL сохраняют прежнюю выдачу с ограничивающей CSP.

При ограничении вложенного файла его URL просмотра/скачивания возвращает HTML с кодом 422, причиной и ссылкой на исходный архив. Обычное успешное скачивание сохраняет прежний URL и содержимое. У неизвестного формата вложенного файла запасная кнопка ведёт на правильный URL его скачивания. Временные файлы процесса удаляются после результата, ошибки или таймаута. Корректность извлечения всех строк смет основным парсером не является результатом этой проверки предпросмотра.
