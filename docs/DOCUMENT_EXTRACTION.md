# Распаковка документов тендера

Разбор берёт исходные архивы только из `data/downloads/<tender_id>`. Старое дерево `extracted` не становится дополнительным входом: вложенные архивы обходятся от исходника с единым бюджетом. ZIP и RAR читаются потоком через `zipfile.open` / `rarfile.open`; `extractall` и распаковка 7z прямо в рабочую папку не используются. Предварительная проверка имён нужна дополнительно к API библиотеки: [документация Python](https://docs.python.org/3/library/zipfile.html), [rarfile](https://rarfile.readthedocs.io/api.html).

На один тендер действуют ограничения: 64 архива, 2000 записей, 5 уровней вложенности, 128 МиБ на исходный архив и отдельный файл, 512 МиБ суммарно после распаковки, коэффициент сжатия не выше 500. Вложенный архив и извлечённые из него файлы входят в один счётчик. Повторное использование сохранённого результата также учитывается в общем бюджете. Процесс ограничен 120 секундами; родитель прекращает зависший процесс и его дочерние обработчики. На Linux дополнительно ограничены память, CPU и размер отдельного файла. На Windows используются установленные 7-Zip/UnRAR, включая стандартные каталоги вне PATH.

Отклоняются абсолютные пути, `..`, ссылки, специальные файлы, неоднозначные/повторяющиеся имена и коллизии файлов с папками. Заявленный и фактический размер проверяются; CRC проверяет архивная библиотека. Ошибка внутри вложенного архива не публикует частичный результат его исходного архива. Распаковка идёт в собственную временную папку; проверенное дерево публикуется переименованием. Исходные файлы не меняются.

Результат хранится внутри `extracted/<tender_id>/<original_stem>/verified-<version>`. Это сохраняет совместимость с существующим переносом старых исходников и их кеша в корзину версий. Для каждого файла журнал содержит относительный путь, цепочку исходных/вложенных архивов, размер и SHA256. Повтор проверяет исходник, политику, ограничения, размеры и хеши файлов. Изменённый производный кеш сохраняется под `invalid-*` и восстанавливается из исходника; он не становится входом для разбора. Версии и карантин автоматически не удаляются.

`reports/ARCHIVES_<tender_id>.json` фиксирует результат последнего запуска. При любой ошибке архива новый отчёт сметы не заменяет предыдущий. Общий поиск продолжает другие тендеры и сохраняет неуспешный для явного продолжения. В карточке видны причина и незавершённость, а прежний отчёт, если он есть, остаётся доступен. Одинаковые имена PDF в разных каталогах больше не объединяют количество распознанных файлов или официальные итоги: `ESTIMATE_PARSE_*` хранит отдельные записи источников. Прежние поля этого JSON сохранены; неоднозначный старый итог по одному имени не применяется сразу к двум файлам.

Пока не поддержаны 7z и зашифрованные/многотомные архивы; причина выводится явно. Предпросмотр содержимого архивов во вкладке документов имеет прежние отдельные ограничения и ещё не перенесён в этот процесс. Этот пакет не доказывает полноту распознавания Excel/PDF, корректность коэффициентов, НДС или экономики; эти проверки — следующие части A4/A6. Данные рабочей базы не мигрируются.
