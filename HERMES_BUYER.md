# Hermes-закупщик: сайт → Mac → черновики

25 сентября 2026. Отдельный профиль `autobot-buyer` работает на Mac mini.
Его локальный API — `http://127.0.0.1:8644`, модель в конфигурации —
`gpt-6-astra` через существующую авторизацию `openai-codex`. Общий шлюз и
действующие профили не перенастраивались. Это **подготовка обращений**:
поиск адресатов, отправка сообщений и приём коммерческих предложений ещё
не подключены. Черновики не увеличивают покрытие ценами.

## Пользовательский сценарий

Тендер → «Поиск цен» → «Запросы поставщикам» → «Подготовить обращения».
Можно сначала отметить строки на вкладке «Позиции сметы». Без выбора берутся
строки без подтверждённой цены, кроме исключённых из отдельного поиска.
Задания разделяются по разделу сметы и типу (материалы, работы, изделия,
услуги), не более 25 строк в группе. Условия и проценты не выдумываются.
Готовые обращения и вопросы раскрываются в том же блоке. Повтор того же
снимка использует существующее активное или готовое задание.

Отмена прекращает приём результата. Уже начатый запуск внутри Hermes может
доработать, но отменённое задание не публикуется. Кнопка не останавливает
другие профили или существующий поиск сайтов.

## Границы и восстановление

- `buyer_jobs.py`: отдельный `data/buyer_jobs.sqlite3`, механизм lease из
  `agent_market_queue`, без изменений БД поиска или рабочих смет.
- `buyer_routes.py`: CRM-сессия и действующие ограничения роли для чтения/
  запуска; worker API `/autobot/api/agent-market/v1/buyer` с отдельным ключом.
  Ключи и lease-токены не возвращаются пользовательскому интерфейсу.
- `buyer_worker.py`: исходящие HTTPS-запросы с Mac, один poller, heartbeat,
  повтор доставки результата после потери подтверждения. Переназначение
  просроченной попытки не даёт старому исполнителю записать результат.
- `hermes_buyer.py`: локальный SQLite-журнал, run_id и результат сохраняются
  до доставки на сайт. Одинаковый снимок не создаёт новый запуск модели.
  Проверяются отдельный профиль, выключенные инструменты и точный состав
  позиций. Это структурная проверка, не подтверждение правильности текста.
- Неоднозначный POST в Hermes остаётся `submission_uncertain`: автоматическое
  повторение запрещено. Неполный ответ — `invalid_result`. Эти состояния
  разбирает оператор, не удаляя журнал. Повтор кнопкой не исправит их.
- Само чтение очереди не доказывает, что Mac доступен: интерфейс пишет
  «Ожидаем закупщика на Mac», пока задание не принято.

Инструменты и каналы у нового профиля отключены. Ключ Hermes хранится только
в его `.env`, доступ владельцу; серверу нужен отдельный ключ очереди
`data/buyer_worker.token` (0600, вне Git). HTTPS-клиент не следует редиректам.
Порт 8644 слушает только localhost; публичного входа в Mac не нужно.

## Исполнитель Mac

Профиль: `/Users/egor/.hermes/profiles/autobot-buyer`.
Сервис Hermes: `ai.hermes.gateway-autobot-buyer` (LaunchAgent).
Исполнитель: `ai.autobot.buyer-worker` (отдельный LaunchAgent).
Код и настройки poller — `connector/`, журнал — `connector/worker.sqlite3`.
Запуск: Python из установленного Hermes, `-m autobot.buyer_worker --config`
с путём к приватному JSON. Поля конфигурации: `queue_url`, `worker_id`,
`queue_token_file`, `hermes_url`, `hermes_env_file`, `journal`.
Авторизация провайдера используется через штатный fallback Hermes,
файлы OAuth не копировались. Standalone API явно включает проверку имени
модели `autobot-buyer`; старый режим `/p/autobot-buyer` сохранён.

## Проверки этого пакета

На изолированной Windows-копии: 22 теста адаптера + 9 тестов очереди/API/
исполнителя PASS; 19 существующих тестов tender_review и agent_market_queue
PASS; три frontend-набора тендера PASS. Browser E2E на копии «Волги»:
выбор, создание, повтор, отмена, reload, раскрытие результата, ошибка и
восстановление, 390/768/1280 без горизонтального переполнения. Визуальные
результаты использовали явно помеченные демонстрационные тексты.
Первый browser POST был отклонён CSRF из-за неразрешённого localhost;
повтор прошёл с разрешённым адресом только тестовой копии. Первый новый
unittest обнаружил незакрытую тестовую SQLite-сессию на Windows; исправлен
тестовый cleanup, все 31 прошли. Полный набор AutoBot не запускался.

Живой отдельный Hermes подготовил три синтетические позиции: кабель 120 м,
прокладка 120 м, знак 6 шт, Ярославская область. Состав и единицы сохранены;
получены 3 черновика и вопросы об условиях. Отправки поставщикам не было.
Проверки опубликованного экземпляра фиксируются ниже после выпуска.

## Выпуск и откат

Перед выпуском: сверить Git/образ/конфигурацию, проверить отсутствие активной
обработки, сохранить rollback-образ и снимки SQLite через backup API.
Новая БД изолирована; миграции существующих данных нет. Контейнерный кандидат
проверяется отдельно. После переключения — health, запрещённый доступ,
исходящий worker, живое задание и чтение результата после перезапуска.
Откат: вернуть сохранённый образ AutoBot и остановить только новый poller;
сохранить новые журнал и очередь для восстановления. Не удалять рабочие БД.

4. Ответы и КП: источник, единицы, НДС, доставка, срок, регион. Только после

## Исправление, выявленное живым прогоном

Hermes v0.17 считает незакрытый SSE-поток завершённого запуска активным.
После первого обращения следующие POST получили явный 429 до создания run_id.
Добавлено чтение/закрытие событий терминального запуска перед доставкой и
следующим заданием; повторный cleanup допускает 404. Только распознанный
429 `rate_limit_exceeded` возвращает тот же локальный снимок в queued;
неоднозначные сетевые ошибки по-прежнему запрещают повторный POST.

Три дополнительных теста довели целевой набор до 34 PASS. Два конкретных
отказа восстановлены в тех же заданиях после сверки лога и обработчика
установленного Hermes: сохранены backup обоих журналов и запись причины,
проверены исходные статусы/run_id. Рабочие сметы и другие агенты не менялись.
